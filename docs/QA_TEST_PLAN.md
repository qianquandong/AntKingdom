# 开发验证、真机试玩与发行测试计划

状态：待执行的客户端测试计划。已有 Python 基线 30 项测试及地图/核心文案检查通过，不代表下列 iOS 项目通过。

## 1. 测试分层与证据

| 层级 | 执行人/工具 | 证明什么 | 不能替代什么 |
|---|---|---|---|
| 规则 | Claude；Python、Swift 单元/差分 | 数值、守恒、路由与状态正确 | 点击手感、渲染、真机 |
| 集成/UI | Claude；模拟器、XCTest/XCUITest | 状态与界面、生命周期适配 | 真机触觉、发热、真实签名 |
| 设备 | 用户或持有设备者；Claude 指导/收集 | 真实安装、性能、触摸、后台、音效 | 用户是否喜欢玩法 |
| 观察试玩 | 用户招募；Codex 分析 | 理解、主动优化、继续尝试 | 长期留存、商业收入 |
| 商业化 | Claude + 用户；StoreKit/Sandbox/TestFlight/测试广告 | 权益、恢复、失败分支、同意 | Apple 审核和生产填充保证 |
| 发行后 | 用户安装商店版；Claude 排查 | 实际分发版本的路径 | 未来版本无回归 |

每条记录包含：测试 ID、commit、app version/build、资源版本、设备/系统、环境、前置存档、步骤、期望、实际、PASS/FAIL/NOT_RUN/BLOCKED、证据位置、执行人、日期。失败附最小复现和缺陷 ID。公开报告去除设备 UDID、账号、邮箱、收据、私人录像和个人姓名。

证据放可访问且受控的位置；仓库 `docs/reports/` 保存脱敏报告，长录像/xcresult 不直接塞进 Git。只改文档不需要假造测试结果。

### 2.1 把开发包实际装到 iPhone

Claude 在 Mac 打开工程，选择 AntKingdom scheme；用户连接并解锁 iPhone、完成信任/配对，按系统要求启用 Developer Mode。在 Xcode 的 Signing & Capabilities 选择用户授权的 Team 和唯一 Bundle ID，选择该实体 iPhone 作为运行目标后 Build & Run。首次安装成功后断开调试器再独立启动一次，核对 build 和保存；截图需能对应测试设备与构建。需要启用开发者模式时参考 [Apple 操作说明](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)。

外部测试改用 TestFlight 安装明确的构建号，测试者不需要拿到开发者账号或 Xcode 工程。任何签名/安装失败原样记录错误，由 Claude 处理；无法安装不能记为“测试通过”。

## 4. 保存、时间与性能

| ID | 动作 | 期望 |
|---|---|---|
| T22 | 挖格/建仓/孵化后杀进程再开 | 原子保存；不重复扣费，不莫名清档 |
| T23 | 后台 30 秒/3600 秒/7200 秒 | 与同效率状态机一致；一小时封顶作用到所有约定时钟 |
| T24 | 连续收到恢复通知、系统时间回拨 | 同一次离线只发一次；负时间归零 |
| T25 | 时区/夏令时变化、跨 UTC 日 | 不额外生成生产时间，商业化计数按约定 |
| T26 | 损坏主存档/主备都坏/写入失败 | 有效备份可恢复；无备份显示错误与重置选择，不静默丢档 |
| T27 | 旧 build 有进度，覆盖安装新 build | schema 迁移正确；章节/外观/卵/奖励状态保持 |
| T28 | 不同存档版本/极端字段输入 | 校验并处理，不崩溃、不产生负资源或超人口 |
| T29 | 全挖+24只+频繁选择/移仓，连续30分钟 | 无崩溃/冻结；记录帧时间、内存、温度趋势 |
| T30 | 进入后台/锁屏/回前台20次 | 不重复循环音、不重复节点、不持续后台渲染 |
| T31 | 静音/音效关/触觉关/减少动态 | 设置生效；关闭反馈不影响核心状态 |
| T32 | 小屏/大字/色觉差异/VoiceOver 检查 | 主按钮可用，状态非仅颜色；不声称支持尚未验证的可访问能力 |

项目性能目标：基准 60Hz 设备持续游玩平均≥55fps，帧时间 p95≤25ms；路线交互无超过 100ms 的可感卡顿；30 分钟后内存不持续单调增长且无系统异常终止。记录采样方法、设备和操作，必要时用 Instruments 查原因。低电量模式单列，不把系统限制误当同一性能样本；这些是内部目标而非 Apple 官方门槛。

## 6. 观察试玩脚本与设计判断

M3 招募 8–12 人；记录匿名编号和游戏经验，不公开姓名。告知是试玩且征求录屏同意。先让其自然玩 5 分钟，不口头教路线；之后给出“让搬运更高效”的目标，再留自由尝试时间；最后问发生了什么、哪次操作有用、为什么想继续/停止。

记录：首次接通用时、是否需提示、首次有效优化及原因、是否自发二次优化、关键卡点。按 PRD 冻结变量判断优化；新源连接不能当同一源效率改善。目标：≥70% 独立接通，≥50% 独立改善且能解释，≥50% 主动再尝试。小样本报告人数/分母，不只写百分比；这些是内部方向门槛，不是市场验证。

M6 再做 20–30 名外部测试者、至少 7 天的稳定性与内容观察。记录实际安装/会话/崩溃及可收集的返回行为，注明统计覆盖范围。没有合法可用的留存数据时明确空缺，不从无输入时长推断喜欢观看。商业化记录理解程度、误触、可选广告使用和外观兴趣，不把沙盒购买当收入。

## 7. 缺陷等级与发布门槛

- **SEV0**：数据丢失、重复真实扣款/权益严重错误、隐私违背、无法启动。立即停止扩大测试/发布，优先修复。
- **SEV1**：核心无法完成、频繁崩溃、恢复购买失败、广告卡死、严重界面不可用。发行阻断。
- **SEV2**：有可接受绕行的表现/体验问题。必须登记影响，用户/Codex 明确接受才可延期。
- **SEV3**：细节美化，排入后续。

M6 必须零未解决 SEV0/SEV1；T01–T48 中当前阶段适用的必测项都通过，阶段尚不适用的标 N/A 并写理由，不能把 BLOCKED 当 N/A。发行候选至少累计 100 次完整测试会话与 10 小时混合机型运行，无可复现崩溃/清档；小样本无崩溃不保证大规模稳定。

改动后按影响回归：改路由跑规则与地图/UI；改保存跑时间/升级；改广告/IAP跑对应服务加生命周期；改资源跑小屏/性能。修完相同候选构建再做一次全链路冒烟，不因一处修复反复重跑无关长测试。
