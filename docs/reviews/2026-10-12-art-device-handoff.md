## 2. P1 / D-16：卵必须保留自己的槽位

现象：`GameScene.renderEggs` 按 count 清空后重新按数组下标绘制。`eggs_two` 夹具中，左卵先孵化，右卵中心由 Queen 左上 `(40,22)pt` 跳到 `(22,22)pt`，横移 18pt。[复核截图](evidence/2026-10-12-egg-slot-jump.png)。不是贴图大小或两态 alpha 的问题。

**表现规则**：两个固定槽中心为 `(22,22)`、`(40,22)pt`。一枚卵从创建到孵化始终占自己的槽；先孵化只移除它自身，另一枚留在原槽。新订单选择空槽；normal/ready 只换纹理，大小固定 24pt。节点与真实卵实例/生命周期绑定，不以当前 count 或排序后的下标作为身份。保持存档兼容；旧存档没有槽位时在加载时确定性分配一次，此后不逐帧重新压紧。若保存新槽位字段，必须可选并覆盖旧存档读入，不为此改经济模型或孵化规则。

连续前后台切换要保留现存卵槽位；冷启动旧存档可一次分配，冷启动新存档若已持久化槽位则应恢复。不要为了纯表现强行破坏核心保存格式，报告采用哪种兼容策略及其边界。

| 用例 | 可复现操作 | 通过标准 |
|---|---|---|
| E01 顺次孵化 | 使用真实 `eggs_two`：两枚剩余 20/25s，停新订单；固定镜头录制 30s | Eggs 2→1→0、Ants 5→6→7；右卵从出生到消失始终在右槽，ready 时不换槽/缩放 |
| E02 填空槽 | 第一枚孵化后允许新订单，原右卵仍未完成 | 新卵占空左槽，右卵的位置、剩余时间、ready 状态不重置；两节点各有一个身份 |
| E03 数量不变 | 同一模拟更新发生一枚孵化并新增一枚，count 前后相同 | 旧卵正确移除、新卵按新剩余时间显示，不能只在 count 改变时更新；无重复节点 |
| E04 同时完成 | 两枚在同一步到期，再创建新订单 | 一次各孵化一次，无残留/重复增蚁；新订单槽位确定且至多两枚 |
| E05 暂停/满仓 | 关闭孵化订单、仓满，再让已有卵完成；另测发行广告主动暂停 | 关订单只停新订单；仓满只让运输待命；已有卵继续。广告主动暂停按 D-14 停模拟，不能混用 |
| E06 生命周期 | 两枚→一枚后 Home/返回、存档读入、旧存档兼容 | 会话内不跳槽；恢复身份/数量/剩余时间正确，符合上述冷启动兼容策略 |

自动化需断言具体卵的节点位置与生命周期，不只检查总数。两 scheme 跑适用用例，标准/小屏录制 E01/E02；同时保留固定镜头 24pt 原尺寸及放大截图。允许数值浮点误差，不允许 18pt 重排。

## 4. P1 / ART_DEVICE_BUILD：实际交付带新美术的设备测试版

本轮核心测试包使用 `AntKingdom`，包含已修 D-13/D-15/D-16 与三批44张资源；不增加商店/广告入口。发行 CrumbKingdom 的美术接入和回归同步完成。新资源批次可以后续独立 build 接入，不能成为一直不交付首个可安装包的理由。

1. 固定候选 SHA、新不可变 tag（例如 `core-art-test-1`）、明确 version/build（build 必须高于旧包2），写清资源版本与安装方法。不要覆盖已有 tag 或复用旧包名。`BUILD.md` 在所交 tag 内必须指向本 tag，不能像旧包文档仍指向 `core-test-d13-1`。
2. 给出该 SHA 的 CI run、构建日志、产物链接、SHA-256、保留期限、bundle 大小增量与资源核对报告。只交 unsigned ZIP 的状态是 BUILD_ARTIFACT_ONLY。
3. 签名条件具备时，用用户授权的 Team/唯一 Bundle ID 在 Mac 生成并安装签名构建，或交付实际可访问的 TestFlight build/邀请。开发签名必须适配目标设备；不能把任意 IPA 当可安装包。账号/证书只在本机或受控 secrets，报告不含凭据。
4. 缺签名权限时准确标 SIGNING_BLOCKED，交付已经编译验证的固定工程/tag 与最短 Mac 操作步骤，列出唯一剩余依赖；不停止其他可做的修复/CI。用户提供的是“有 Mac”，不是已给出 Team/证书。
5. 最少一台物理 iPhone 安装启动，回填型号/iOS、version/build、代码SHA、资源版本、安装渠道。截图必须能看见新蚂蚁/卵和房间；短视频覆盖 E01、挖掘/运输/移仓、后台65s返回总结；保存/杀进程恢复无丢失或重复收益。
6. 继续完成 #11 设备矩阵（包括短离开、1h、2h上限、锁屏和冷启动等适用项）。先交可安装新美术包，再收齐终验；缺的项目保持 NOT_RUN，不能以模拟器绿灯关闭设备交付。

交付状态分开填写：`CODE_TESTS_PASSED` → `BUILD_ARTIFACT_ONLY` → `SIGNED_INSTALLABLE` → `DEVICE_SMOKE_PASSED` → `DEVICE_ACCEPTANCE_PASSED`。目前仅旧包 unsigned 产物成立，后三级未成立。
